# Sockets ודואר: SMTP, POP ו-IMAP

> 🔑 **בשורה אחת:** סוקט הוא הדלת שדרכה תהליך שולח וקולט הודעות מהרשת. בשרת TCP יש סוקט **האזנה** אחד ועוד סוקט **חיבור** לכל לקוח שהתקבל. דואר נדחף בין שרתים ב-**SMTP** (push), ונמשך מהשרת של הנמען ב-**POP3** או **IMAP** (pull).

## מה המבחן שואל

- **כמה sockets נוצרו או נפתחו**: בצד הלקוח בלבד (23A-A שאלה 7, 23A-B שאלה 9) או בשני הצדדים (22S-A שאלה 9).
- **סדר קריאות ה-API** לסוקטים בשרת ובלקוח (25A-B שאלה 13).
- **תהליך שליחת הדואר** מ-User Agent אל User Agent (25A-A שאלה 12).

## סוקטים

תהליך מזוהה ברשת על ידי **כתובת IP ומספר פורט**. סוקט הוא ה"דלת" של התהליך. **UDP:** בלי חיבור, כל הודעה נשלחת בנפרד ליעד שנקבע בה. **TCP:** סוקט מזוהה על ידי ארבעיית (IP מקור, פורט מקור, IP יעד, פורט יעד), ולכן שרת אחד משרת הרבה לקוחות על אותו פורט.

**סדר הקריאות ב-TCP.**

| שרת | לקוח |
|---|---|
| `socket` יוצר סוקט | `socket` יוצר סוקט |
| `bind` קושר אותו לפורט | |
| `listen` מאזין | |
| `accept` ממתין ללקוח ומחזיר **סוקט חיבור חדש** | `connect` פונה לשרת (לחיצת יד) |

`listen` תמיד אחרי `bind`, ו-`accept` אחרי `listen`. הלקוח רק `socket` ואז `connect`. בשרת: סוקט ההאזנה נשאר, וכל לקוח מקבל סוקט חיבור משלו.

## מתכון: כמה sockets?

1. **בצד הלקוח:** סוקט **UDP** לכל שאילתת DNS (אם היעד אינו מוכר ויש שם), ואחריו סוקט **TCP** לכל חיבור HTTP שנפתח. בספירת חיבורים ראו [[http]]: ב-HTTP/1.1 persistent כל האובייקטים משרת אחד עוברים על חיבור אחד.
2. **בצד השרת:** סוקט האזנה אחד (נוצר כשהשרת עלה), ועוד סוקט חיבור אחד לכל חיבור שהתקבל.
3. סוכמים את הצדדים שהשאלה מבקשת.

דוגמאות:
- 23A-A שאלה 7 ו-23A-B שאלה 9: האתר חדש ללקוחה, כל התמונות על אותו שרת, HTTP/1.1. צד הלקוח: סוקט DNS אחד ועוד סוקט TCP אחד ל-HTML ולכל התמונות (persistent): **2**. תשובות כמו 7 או 8 מניחות חיבור לכל תמונה, ותשובה של 1 שוכחת את ה-DNS.
- 22S-A שאלה 9: דף עם HTML בלבד. שרת: סוקט האזנה וסוקט חיבור, כלומר 2. לקוח: סוקט UDP ל-DNS וסוקט TCP ל-HTTP, כלומר 2. סך הכול **4**. מי ששכח את סוקט ה-DNS או את סוקט ההאזנה מקבל 3.

## דואר אלקטרוני

**רכיבים:** User Agent (תוכנת הדואר), שרת דואר (mail server) עם תיבות הנמענים ותור הודעות יוצאות, ו-SMTP.

**מסלול הודעה:** ה-User Agent של השולח שולח את ההודעה לשרת הדואר שלו. שרת הדואר של השולח פותח **חיבור TCP** לשרת הדואר של הנמען ומעביר את ההודעה ב-**SMTP**. ההודעה נשמרת בתיבת הנמען, והנמען קורא אותה כשהוא מפעיל את ה-User Agent שלו (25A-A שאלה 12). אין שליחה ישירה מ-User Agent ל-User Agent, ואין "שרת גלובלי".

**SMTP הוא push:** השולח דוחף. החיבורים persistent, ההודעה בטקסט 7-ביט ASCII, והסוף מסומן בשורה של נקודה. **HTTP הוא pull:** הלקוח מבקש. בניגוד ל-HTTP, ב-SMTP כמה אובייקטים נשלחים יחד בהודעה אחת (multipart).

**איסוף הדואר משרת הדואר של הנמען** הוא פרוטוקול אחר: **IMAP** (ההודעות והתיקיות נשארות בשרת, והלקוח מנהל אותן שם), **POP3** (הורדה אל הלקוח) או HTTP (דואר אינטרנטי כמו Gmail, שמעליו יש SMTP לשליחה). SMTP אינו משמש לקריאה על ידי הנמען.

## דוגמה

דני שולח הודעה לרות: ה-User Agent של דני מעביר לשרת הדואר של דני. השרת פותח TCP לשרת הדואר של רות (בפורט 25) ומעביר ב-SMTP. הודעה נשמרת בתיבה של רות. רות מפעילה את התוכנה, והיא מושכת את ההודעה ב-IMAP או POP3.

## מלכודות

> 🪤 **סוקט האזנה נשכח.** בשרת תמיד יש סוקט האזנה בנוסף לסוקטי החיבור.

> 🪤 **סוקט DNS נשכח.** כשהשם אינו ידוע ללקוח, שאילתת DNS פותחת סוקט נפרד, UDP.

> ⚠️ **persistent אינו מכפיל סוקטים.** שרת אחד, חיבור אחד, גם אם יש לדף חמש תמונות. הערה: תמונות משרת **אחר** דורשות חיבור נוסף.

> ⚠️ **סדר ה-API.** מי ש"מקבל" (`accept`) חייב כבר להיות בהאזנה (`listen`) וכבר קשור לפורט (`bind`).
